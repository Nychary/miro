# Конструктор уроков для Miro

Панель внутри доски Miro, которая собирает готовый урок по физике или английскому:
теорию, формулы, задачи, интерактивные задания и отдельный фрейм с ответами
для преподавателя.

## Как это работает — «бумажный мост»

Приложение не ходит в нейросеть само. Панель собирает готовый промпт, репетитор
вставляет его в тот чат, которым уже пользуется, и приносит ответ обратно:

```
[панель]  форма → промпт в буфер
                                   → любой чат с нейросетью →
[панель]  ответ → разбор JSON → движок раскладки → объекты на доске
```

Так задумано, а не за неимением лучшего:

- **Ничего не стоит и ничего не требует.** Ни ключа, ни сервера, ни подписки.
  Приложение остаётся статической страницей.
- **Работает с любой нейросетью** — с той, к которой у репетитора уже есть доступ.
- **Содержание проходит через человека до того, как попадёт на доску.** Нейросети
  ошибаются в физике: путают знаки, единицы, ответы к задачам. Промпт требует
  самопроверки, разбор ответа сверяет ответы с задачами и пропуски с ключами,
  но последнее слово остаётся за репетитором — и это правильно.

Цена — два копирования на урок. Когда это надоест, переход на автоматический
режим с API-ключом стоит около 5–10 долларов в месяц при десяти уроках в неделю
и сводится к одной новой реализации того же интерфейса: промпты, схема,
валидация и рендерер уже общие.

## Устройство

Ключевое разделение: **описание урока не содержит координат**. В нём есть
«теория из четырёх тезисов» и «шесть задач», но нет ни одного числа про пиксели.
Всё оформление живёт в `src/render`. Поэтому нейросеть отвечает только за
содержание, а вёрстку считает обычный детерминированный код.

| Файл | Зачем |
|---|---|
| [src/lesson/schema.ts](src/lesson/schema.ts) | Модель урока. Центральный контракт проекта |
| [src/lesson/prompt.ts](src/lesson/prompt.ts) | Сборка промпта: структура под предмет и длительность, схема, требования к содержанию |
| [src/lesson/validate.ts](src/lesson/validate.ts) | Разбор ответа: снимает обёртку, проверяет содержимое, объясняет ошибки по-русски |
| [src/lesson/samples.ts](src/lesson/samples.ts) | Два настоящих урока — образец для отладки вёрстки |
| [src/render/theme.ts](src/render/theme.ts) | Все размеры, отступы и цвета |
| [src/render/canvas.ts](src/render/canvas.ts) | Прослойка над Web SDK: курсор, габариты, примитивы |
| [src/render/composition.ts](src/render/composition.ts) | Секции, карточки, сетки, колонки |
| [src/render/blocks.ts](src/render/blocks.ts) | По рендереру на каждый тип блока |
| [src/render/renderLesson.ts](src/render/renderLesson.ts) | Сборка урока и упаковка во фрейм |
| [src/render/metadata.ts](src/render/metadata.ts) | Разметка для будущей автопроверки заданий |

Три особенности, которые определили устройство кода:

1. **Высоту текста в Miro нельзя посчитать заранее** — её решает сам Miro, когда
   переносит строки. Поэтому текст сначала создаётся, потом у него читается
   фактическая высота, и только после этого он ставится на место.
2. **Объекты не прикрепляются к фрейму сами.** Фрейм создаётся последним, уже по
   фактическим габаритам содержимого, а объекты складываются в него явно.
3. **Ответ приходит из буфера обмена, то есть в каком угодно виде.** Разбор
   снисходителен к обёртке — markdown-забор, «конечно, вот ваш урок» перед JSON,
   фигурная скобка внутри условия задачи — и строг к содержимому.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Дальше приложение нужно один раз зарегистрировать в Miro:

1. Завести Developer team на [developers.miro.com](https://developers.miro.com)
   и создать в ней приложение.
2. В настройках приложения вставить содержимое [miro-manifest.yml](miro-manifest.yml).
3. Установить приложение в свою команду.
4. Открыть любую доску, нажать «+» на левой панели и выбрать «Конструктор уроков».

Пока `sdkUri` указывает на `http://localhost:3000/`, приложение работает только
при запущенном `npm run dev`.

## Публикация

Пока `sdkUri` в манифесте указывает на `http://localhost:3000/`, панель работает
только при запущенном `npm run dev`. Чтобы развязаться с локальным сервером,
её достаточно опубликовать как статический сайт — бэкенда у приложения нет.

В репозитории лежит [готовый workflow](.github/workflows/deploy.yml) для GitHub
Pages. Что нужно сделать один раз:

1. Создать на GitHub репозиторий и запушить в него проект.
2. В репозитории: **Settings → Pages → Source → GitHub Actions**.
3. Дождаться, пока пройдёт сборка на вкладке **Actions**. Адрес сайта появится
   там же — вида `https://<логин>.github.io/<репозиторий>/`.
4. В настройках приложения Miro поменять в манифесте две вещи:

```yaml
sdkUri: https://<логин>.github.io/<репозиторий>/
boardPicker:
  allowedDomains:
    - <логин>.github.io
```

После этого приложение работает всегда, а `npm run dev` нужен только для
разработки. Каждый следующий push пересобирает и публикует панель сам.

**Про публичность.** На бесплатном тарифе GitHub Pages работает только из
публичного репозитория, то есть код проекта будет виден всем. Для этого кода
это не страшно: секретов в нём нет и не появится, пока генерация идёт через
буфер обмена. А вот учебники и авторские материалы репетитора в репозиторий
не попадают — папка `materials/` закрыта в `.gitignore`.

Если публичный репозиторий не подходит, панель так же разворачивается на
Cloudflare Pages или Netlify прямой загрузкой папки `dist` — меняется только
адрес в манифесте.
